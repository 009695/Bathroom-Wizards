# Code style, Kent Trades prototype

## Writing

- **No em dashes or en dashes anywhere**, including their HTML entity forms (the `mdash` and
  `ndash` entities). Use commas, full stops, colons, brackets, or the word "to" for ranges.
  This is enforced by a hook, so a write containing one will be rejected.
- Write the way a Medway tradesperson would talk to a customer. Plain, direct, no marketing filler.
  "We turn up when we say we will" beats "customer centric service delivery".
- British spelling and £ formatting throughout.
- Prices are always written as "from £X" so nobody reads them as a fixed quote.
- **Never print prices on the business cards.** They outlive the prices. Cards carry a QR code to
  the site, where prices can be changed without a reprint.

## HTML

- Static HTML. No framework, no build step, no bundler. The people who own this are tradespeople,
  and a static site cannot break at 8pm on a Sunday.
- JavaScript only where there is no CSS alternative. Currently that is the mobile nav toggle, and
  nothing else.
- One page per site. Sections are anchors, not routes.
- Use HTML entities for currency and symbols (`&pound;`, `&times;`, `&middot;`) so encoding
  problems cannot mangle a price.
- Every image needs a real `alt` describing the actual work shown. Decorative images take `alt=""`.
- Photos below the fold take `loading="lazy"`.

## CSS

- Everything shared lives in `assets/css/base.css`. Per site overrides go in a `<style>` block in
  that site's `<head>`, and only when the difference is genuinely brand specific.
- Brand theming is done by swapping custom properties under `html[data-brand="..."]`.
  Never hard code a brand colour in a component rule.
- **Always write auto fit grids as `minmax(min(NNNpx, 100%), 1fr)`.** The bare
  `minmax(NNNpx, 1fr)` form overflows on phones whenever the grid sits inside a padded container.
  This bit us once already in the contact card.
- Use `clamp()` for type and section spacing rather than a stack of breakpoints.
- Prefer logical shorthands (`padding-inline`, `margin-inline`) where they read more clearly.

## Print (cards and datasheet)

- Dimensions in `mm`, type in `pt`. Never `px` in a print stylesheet.
- Cards are 85x55mm plus 3mm bleed all round, so the page box is 91x61mm. Keep content 6mm in
  from the bleed edge.
- Screen only presentation (the grey desk background, the paper drop shadow) belongs inside
  `@media screen`. If it leaks into print it fights the `@page` box and adds a blank page.
- Always set `print-color-adjust: exact` on backgrounds that must actually print.
- **After any print edit, re render and check the page count.** The datasheet is one A4 page with
  almost no slack, and the cards must stay at exactly 6 pages (3 designs, front and back).

## Assets

- Photos: max 1400px wide, progressive JPEG, quality 82. Run them through the resize step rather
  than committing camera originals.
- Logos are PNG with a genuinely transparent background so they work on dark and light.
- QR codes are SVG, generated by `print/make-qr.py`, never hand edited. Regenerate from the base
  URL so all codes stay in step.
- Use error correction level H on QR codes. They end up on cards in a work van.

## Verifying before you call it done

- Check for horizontal overflow at a real phone width, not just a narrow desktop window.
  Headless Chrome clamps at 485px, so test inside a 360px iframe.
- Decode the QR codes from the rendered PDF, not from the source SVG. That is what the printer
  produces and what a customer's phone will actually see.
- Confirm every local `src` and `href` resolves before publishing.
